# OpenCode Native Swarms v0.1.1

## What ships

- The `swarm-tester` command allowlist now includes the canonical `bun run check` and `bun run typecheck` commands.
- The tester remains restricted to exact, argument-free commands.

## Security boundary

The existing deny-by-default boundary is unchanged. Arbitrary script names,
arguments, and shell composition remain denied. Stage one cannot edit files,
commit, push, merge, create pull requests, or write to external services.
Test commands execute project code and must be used only in repositories you
trust.

## Verification

The local release-preparation checks are:

```bash
bun run check
bun run package:check
```

The installed-plugin dogfood trial must separately populate
`docs/dogfood/v0.1.1.md`; the empty template is not evidence that the release
gate has passed.

## Issue #3 closure condition

Issue #3 is closed only after the installed plugin demonstrably allows both
exact commands through `swarm-tester` while continuing to deny arbitrary
script names, added arguments, and shell composition, with the results recorded
in the dogfood report.

## Known limitations

- Repository-owned scripts are trusted project code: an exact allowed command
  can execute whatever that repository's script invokes.
- Installation is from a persistent local checkout; this release is not
  published to npm.
- Background subagents remain an experimental OpenCode feature.
- Models are intentionally inherited from user configuration and are not
  pinned.
