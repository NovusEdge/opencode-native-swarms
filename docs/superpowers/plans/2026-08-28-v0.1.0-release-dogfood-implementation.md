# v0.1.0 Release and Dogfood Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Protect `main`, prove five real read-only swarm workflows—including parent-session responsiveness—and publish the tested code as the public GitHub-only `v0.1.0` release.

**Architecture:** A controller creates one isolated release worktree and durable runtime-state file. Luna implementers prepare and verify each bounded task; the controller performs the already-authorized GitHub mutations. Attached OpenCode sessions prove that the primary session answers while a child remains busy. Sanitized evidence becomes a documentation-only pull request, and the release tag targets that exact merge.

**Tech Stack:** OpenCode 1.18.25, OpenCode HTTP/CLI session APIs, Bun, uv/pre-commit, Git, GitHub Actions, and GitHub CLI/REST API.

**Spec:** `docs/superpowers/specs/2026-08-28-v0.1.0-release-dogfood-design.md`

## Global Constraints

- The release is GitHub-only; never publish to npm or another registry.
- Do not add a writer, expand permissions, build a Codex port or workflow language, pin a model, or add unrelated features.
- Every trial uses `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true`, omits `--model`, and never uses `--auto`.
- Run trials only in this trusted repository against one recorded clean candidate commit.
- Do not commit raw event streams, model transcripts, secrets, local absolute paths, or private configuration.
- `git status --porcelain` must be empty before and after every trial.
- Parent responsiveness is mandatory: a trial fails unless the parent responds while at least one child session remains `busy` both immediately before and immediately after that response.
- Across the five trials, the observed role set must be exactly `workflow-director`, `swarm-researcher`, `swarm-reviewer`, and `swarm-tester`.
- Create one issue per stable finding identifier; observations remain only in the dogfood report.
- The release tree may differ from the dogfood candidate only at `docs/dogfood/v0.1.0.md` and `docs/releases/v0.1.0.md`.
- Never move or replace the published `v0.1.0` tag.
- Implementer agents use `gpt-5.6-luna`, never spawn subagents, and preserve other agents' changes.

The user explicitly authorized this rollout, including the repository ruleset,
finding issues, branch pushes, pull requests, merges, the annotated tag, and the
public GitHub release. The controller owns those mutations, rechecks the exact
target and payload immediately before each, and stops if either differs from
this plan. Luna workers prepare payloads, run local/read-only operations, and
verify resulting external state.

## Attached Trial Protocol

Every trial follows this protocol; task sections provide only the unique title
and objective.

1. Record `date -u +%Y-%m-%dT%H:%M:%SZ`, require a clean worktree, and start
   `opencode serve` from the release worktree through the execution tool with a
   one-second yield:

   ```bash
   set -euo pipefail
   source '/home/novusedge/Projects/opencode-native-swarms/.worktrees/v0.1.0-release-dogfood/.superpowers/sdd/2026-08-28-v0.1.0-release-dogfood-implementation/runtime.env'
   OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true opencode serve --hostname 127.0.0.1 --port 0 --print-logs --log-level WARN
   ```

   Record the printed loopback URL and execution-session identifier in the
   trial's SDD state file. Never expose the server beyond `127.0.0.1`.

2. Create an isolated parent session and record its ID:

   ```bash
   set -euo pipefail
   source '/home/novusedge/Projects/opencode-native-swarms/.worktrees/v0.1.0-release-dogfood/.superpowers/sdd/2026-08-28-v0.1.0-release-dogfood-implementation/runtime.env'
   curl -fsS -X POST "${SWARM_SERVER_URL}/session" -H 'Content-Type: application/json' -d "{\"title\":\"${SWARM_TRIAL_TITLE}\"}" | jq -er '.id'
   ```

3. Invoke `/swarm` in that parent with the task's exact objective plus this
   exact suffix:

   ```text
   Launch the named background workers, then return immediately with their task IDs without waiting for completion. Do not synthesize yet.
   ```

   Use:

   ```bash
   set -euo pipefail
   source '/home/novusedge/Projects/opencode-native-swarms/.worktrees/v0.1.0-release-dogfood/.superpowers/sdd/2026-08-28-v0.1.0-release-dogfood-implementation/runtime.env'
   SWARM_WORKER_SUFFIX='Launch the named background workers, then return immediately with their task IDs without waiting for completion. Do not synthesize yet.'
   SWARM_FULL_PROMPT="${SWARM_OBJECTIVE} ${SWARM_WORKER_SUFFIX}"
   opencode run --attach "${SWARM_SERVER_URL}" --session "${SWARM_PARENT_SESSION_ID}" --dir "${SWARM_RELEASE_WORKTREE}" --format json --command swarm "${SWARM_FULL_PROMPT}"
   ```

4. Prove at least one child is busy, prompt the parent, then prove a child is
   still busy. The checks must fail the shell when the condition is false:

   ```bash
   set -euo pipefail
   source '/home/novusedge/Projects/opencode-native-swarms/.worktrees/v0.1.0-release-dogfood/.superpowers/sdd/2026-08-28-v0.1.0-release-dogfood-implementation/runtime.env'
   SWARM_CHILDREN=$(curl -fsS "${SWARM_SERVER_URL}/session/${SWARM_PARENT_SESSION_ID}/children")
   SWARM_STATUSES=$(curl -fsS "${SWARM_SERVER_URL}/session/status")
   SWARM_BUSY_BEFORE=$(jq -nr --argjson children "${SWARM_CHILDREN}" --argjson statuses "${SWARM_STATUSES}" '[ $children[].id | select($statuses[.].type == "busy") ] | first // empty')
   test -n "${SWARM_BUSY_BEFORE}"
   SWARM_PARENT_JSON=$(opencode run --attach "${SWARM_SERVER_URL}" --session "${SWARM_PARENT_SESSION_ID}" --dir "${SWARM_RELEASE_WORKTREE}" --format json "While a background assignment remains pending, respond exactly PARENT_AVAILABLE and do not wait for or summarize any worker.")
   test "$(printf '%s\n' "${SWARM_PARENT_JSON}" | jq -rs '[.[] | select(.type == "text") | .part.text] | last')" = "PARENT_AVAILABLE"
   SWARM_CHILDREN=$(curl -fsS "${SWARM_SERVER_URL}/session/${SWARM_PARENT_SESSION_ID}/children")
   SWARM_STATUSES=$(curl -fsS "${SWARM_SERVER_URL}/session/status")
   jq -en --argjson children "${SWARM_CHILDREN}" --argjson statuses "${SWARM_STATUSES}" 'any($children[].id; $statuses[.].type == "busy")'
   ```

   The parent's final assistant text must equal `PARENT_AVAILABLE`. If no child is
   busy before or after, the trial does not demonstrate responsiveness. Retry
   that trial once with two non-overlapping assignments; a second failure is a
   release blocker.

5. Ask the same parent to collect actual results:

   ```bash
   set -euo pipefail
   source '/home/novusedge/Projects/opencode-native-swarms/.worktrees/v0.1.0-release-dogfood/.superpowers/sdd/2026-08-28-v0.1.0-release-dogfood-implementation/runtime.env'
   opencode run --attach "${SWARM_SERVER_URL}" --session "${SWARM_PARENT_SESSION_ID}" --dir "${SWARM_RELEASE_WORKTREE}" --format json "Collect the launched assignments now. Synthesize only delivered results for the original objective, with the requested evidence and explicit failures or unresolved uncertainty."
   SWARM_CHILDREN=$(curl -fsS "${SWARM_SERVER_URL}/session/${SWARM_PARENT_SESSION_ID}/children")
   SWARM_STATUSES=$(curl -fsS "${SWARM_SERVER_URL}/session/status")
   jq -en --argjson children "${SWARM_CHILDREN}" --argjson statuses "${SWARM_STATUSES}" 'all($children[].id; (($statuses[.]?.type // "idle") != "busy"))'
   ```

6. Require all child sessions to be non-busy, require a clean worktree, record
   the finish timestamp, and stop the server with Ctrl-C through its execution
   session. Summarize only the evidence required by the trial template; discard
   the raw JSON output.
